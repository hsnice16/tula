# 12 · Every key, listed where somebody looks for it

**Status**: done
**Covered by**: `src/ui/keymap.test.ts`, `src/ui/screen.test.ts`, `src/consistency.test.ts`

## Goal

tula has grown the `/` menu, the ctrl+s palette, ctrl+o, ctrl+r, Readline
editing, completion and suggestions, vim mode and newline keys, and there is no
one place that lists them. `/help` lists commands. The keys that are written
down are written down by hand, in a placeholder string, `README.md`'s Status
row, `AGENTS.md`, the site's frame (`site/components/Session.tsx`) and the
security page — each a copy that drifts from `src/ui/keys.ts` and `app.tsx`, and
nothing checks any of them against the keys that actually work.

## What is standard

| Tool | In the app | Hint | Docs, and how they stay true |
|---|---|---|---|
| Claude Code | `?` on an empty prompt toggles a shortcuts panel; `?` after text is a character; Esc closes it | — | "Keyboard shortcuts" tables in `code.claude.com/docs/en/interactive-mode`; `keybindings` |
| Codex CLI | `?` opens the shortcut overlay (`codex-rs/tui/src/bottom_pane/footer.rs`, `FooterMode::ShortcutOverlay`) | "? for shortcuts", the first hint dropped on a narrow terminal (same file) | overlay drawn from the `SHORTCUTS` table beside `keymap.rs` |
| Gemini CLI | `?` on an empty prompt toggles a panel above the input | — | `docs/reference/keyboard-shortcuts.md`, generated from `keyBindings.ts` by `scripts/generate-keybindings-doc.ts`, whose `--check` fails CI on a stale doc |
| lazygit | `?` menu, grouped Local / Global / Navigation | bottom key line | `docs/keybindings/Keybindings_en.md`, generated |
| k9s, htop, tig, less | `?`, F1 or `h` | htop's function bar | — |
| nano, mc | — | a key footer | — |

Agreed: a `?` panel on an empty line, a short hint pointing at it, a docs page
grouped by what the keys are for, and a platform or terminal limit stated on
the row it limits — Claude Code marks Alt rows "Requires Option as Meta on
macOS" and states which terminals send Shift+Enter; Codex shows whichever
newline key will work in the terminal it is running in.

Split: lazygit, tig and k9s filter the list to the current view; the terminal
AI tools show one list for the prompt. tula is a prompt, so it takes the
second, and shows vim's rows only while vim is on. Only Gemini CLI and lazygit
generate the docs from the keymap and fail the build when they drift — and
that is the half this repository's own rule already asks for: a claim is
rendered from the code or pinned by a test.

### Decisions

- **The keymap is `src/ui/keymap.ts`**, one list of entries, each holding its
  keys as displayed, what it does, its group and an optional note. `keys.ts`
  reads its bindings from the same entries.
- **The panel opens with `?` on an empty line, and in vim NORMAL**, as Claude
  Code and Gemini CLI do. It closes on Esc or `?`. Typing into a non-empty line
  inserts `?`.
- **The drift check is a test**, as Gemini CLI's is: `src/ui/keymap.test.ts`
  renders the reference and fails when `README.md`'s marked section or the
  site's page differs. `bun run keys:docs` rewrites the marked section, a
  script in the shape of Gemini CLI's generator.
- **The site gets a page of its own, `/keys`.** `AGENTS.md` keeps the overview
  to two arguments and puts a reference on neither of the other pages, and
  `NAV` then carries it into the header, the sitemap and `llms.txt`.
- **The site reads `site/lib/keys.json`.** The site is a separate package and
  cannot import the keymap. Biome lays out a generated module or JSON
  differently from what the generator writes, so a byte-for-byte check would fail
  on layout alone. The file is left out of `site/biome.json` for that reason.
- **The panel sits above the input and fits the rows it has.** Twenty-odd rows
  of keys are taller than a small terminal, and a frame taller than the viewport
  is one Ink clears on every keystroke. So the panel shows what fits and ends on
  a line naming `/keys` for the rest. Any other key closes it and then does
  what it does, as Gemini CLI's panel does.
- **`/keys` prints every group, vim's included and titled "after /vim".** It
  runs on the command line too, where there is no vim mode to ask about; the
  panel is the one that follows the mode.
- **The hint is "? for shortcuts" at the end of the placeholder**, dropped
  whole when the row cannot hold it, as Codex drops it first.
- **The newline rows** say ctrl+j works in every terminal, and each other
  newline key names what limits it.

## Acceptance

- **One keymap.** A module under `src/ui/` holds every binding: the keys, what
  it does, its group (general, editing, history, lists and completion,
  multi-line, vim), and any note that belongs on its row — Option as Meta on
  macOS, a newline key that needs a terminal able to send it. `keys.ts` and the
  handlers in `app.tsx` read from it, so a key cannot work without being listed,
  and a test walks every entry through the handler to prove each listed key
  does something.
- **`?` on an empty line opens the list**, above the input, grouped as the
  keymap groups it; `?` after text is typed as a character; Esc or `?` again
  closes it. Vim's rows appear while vim is on. It is a panel, not a modal, and
  it holds to the frame rules `AGENTS.md` states: every row fits the width, and
  `src/ui/screen.test.ts` covers it at the four widths and across a resize.
- **`/keys`** prints the same list, so the one-shot CLI and the ctrl+s palette
  reach it; it goes through `src/cli/registry.ts` like any command, and
  `src/consistency.test.ts`'s covered set names it.
- **One hint.** The input placeholder gains "? for shortcuts", the first part
  dropped when the width cannot hold it, as Codex drops it. `/help` ends with a
  line pointing at `?` and `/keys`.
- **A docs section generated from the keymap**: in `README.md` between markers,
  and on the site where the reference belongs — a page of its own if the site's
  rules put it there, with `site/lib/site.ts`'s nav, sitemap and `llms.txt`
  following. Regenerated by a script, and a test fails when the committed text
  differs from what the keymap renders.
- **Every key the prose already names is held to the keymap**:
  `site/components/Session.tsx`'s `KEYS` and hint strings, the security page's
  key mention, the hint strings in `app.tsx`, and the keys `AGENTS.md` names. A
  key named anywhere that the keymap does not hold fails the build, in the shape
  `src/site-claims.test.ts` already uses for commands and chains.
- **A newline key a terminal may not send says so on its row**, and ctrl+j is
  listed as the one that works everywhere — never a row claiming Shift+Enter
  works unconditionally.

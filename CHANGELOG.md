# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions
follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). A version is
chosen when a release is cut, from what went into it — [ROADMAP.md](./ROADMAP.md)
tracks the milestones and states the bump rules.

This is the consumer-facing log: what changes a number tula reports, what it
reads, what it refuses, or how you install it. What does **not** belong here —
CI and build plumbing, refactors, and doc-only edits — stays in commit messages.

## [Unreleased]

## [0.1.2] - 2026-09-06

### Changed

- **`/update install` says how far the download has got.** It pulls the same tens of megabytes the installer does and awaited the whole body in one call, so the status line read `working` for all of it — the hang `install.sh` used to look like, in the one place tula replaces its own binary. The body is read in chunks now and the line counts them off: `downloading 57% · 11.9 of 20.8 MB`, or the bytes alone where the asset host sends no length. Nothing else about the update path moved: the checksum is still checked before anything is unpacked, and a version that is not newer is still refused.
- **The hero frame on the site shows the tool's name again.** The frame is anchored to its bottom and clipped at the top, which is the only direction a terminal loses a row — and the working-directory line added to the banner made that block one row taller than the frame could hold, so the row it dropped was the one reading `tula v0.1.1`. The frame is a row deeper to fit it.
- **The site reads at contrast on a phone, and its taps are big enough to hit.** Section labels — the heading above every block on every page — were drawn at 3.05:1, below the 4.5 that text that size needs to be read; so were the `curl` flag legend, the line telling you to read the script before piping it into a shell, and what enforces each promise on the security page. All of them take the same grey the prose does now, which passes at 5.26. The copy button on each command was 22px tall and the footer links 21, under the 24 a target needs: the button's tap area now reaches past the chip without the chip moving, since the title bar it sits in is drawn around it. At 200% text zoom the install page had started scrolling sideways, because one channel tab could not wrap and an environment variable is a single unbreakable word; both give now. The one thing still drawn faint is the transcript inside a terminal frame, which is a picture of dim terminal output and reads as wrong lighter.
- **The site is picked up properly by a phone and a crawler.** An `apple-touch-icon`, so adding the page to an iOS home screen gets the mark rather than a screenshot of the page — served from a route with the extension in its name, because Next's own convention writes the file without one and a static host then serves an image as a byte stream. The 404 no longer claims the front page as its canonical, which it had inherited.

## [0.1.1] - 2026-09-06

### Changed

- **A version you already have is not downloaded again.** The installer resolved the version and then downloaded and re-verified the whole 21 MB archive regardless of whether that exact build was already on disk — so the install line pasted a second time, which is how most people fix a PATH problem, paid the full download to arrive at the file it already had. It now recognises the version under `~/.tula/versions` and goes straight to relinking and the PATH line — 2.7s to 0.3s on a warm link, and from minutes to under a second on a cold one. `TULA_FORCE=1` fetches and checks again for anyone who wants that. The short cut needs the launcher symlink to be there already, not just a directory: anyone able to write under the install tree could otherwise plant a version directory before tula was ever installed and have the first install adopt it unread, where that install used to download over it.
- **The download says how far along it is.** `-s` silenced curl's meter for every fetch, including the one that takes minutes, so a single `downloading` line sat unchanged for the whole transfer and read as a hang — 152 seconds of silence, in one capture, between the first line and the next. The download is GitHub's and is not faster; it is now visibly moving. The archive keeps the meter now; the 386-byte checksum file does not. A transfer under 1 KB/s for 30 seconds is ended rather than waited on, which is the difference between a slow link and a dead one.
- **Paths in the installer's report are written from home.** `~/.tula/bin/tula` rather than the absolute form, which is mostly the reader's own username and the part they would redact before pasting a screenshot into an issue. The `export PATH=` line stays absolute, because a `~` inside those quotes is not a home directory to any shell.
- **The banner carries a `v` before the version, and the directory you are in.** The `v` is how the tag, the release and every `git` and `npm` line about the build already spell it; the bare number was the odd one out. The directory is written from home too, which keeps the reader's own username off a screenshot. tula reads nothing from it — the book is the same wherever the shell was opened — but it is what tells two terminals apart at a glance. It is stripped of control characters and capped like any other text tula did not write: every byte but `/` and NUL is legal in a directory name, so a cloned repository can carry one named to repaint whatever draws it.

## [0.1.0] - 2026-09-06

The first release: real venues on a published install path, the query shell, and
the answer it exists to give — one net exposure per asset across venues, and
what breaks first.

### Added

- **Eight venues, three of them needing no credential at all.** Hyperliquid — perps with liquidation price and leverage, spot, and withdrawable margin, from a public address; verified against a live 176-position account. Aave v3 on Ethereum — per-asset collateral and debt with the account health factor over batched `eth_call`, reserves discovered on-chain rather than from hardcoded addresses; verified at health factors of 1.37 and 9.99. Wallet — native ETH and every ERC-20 on the Token Lists standard, with Aave receipt tokens excluded so a balance never double-counts collateral Aave already reports; verified against an address holding 65 tokens. Then Kraken (spot and staked balances from a query-only key), Binance (spot balances, scope proven from `apiRestrictions` — its futures permission grants trading, so a key that could read futures is refused), Coinbase Advanced (CDP keys over JWT, proven from `key_permissions`), Stripe (balances per currency from a restricted `rk_` key — an `sk_` key can create payouts, so it is refused rather than reported unknown), and Circle Mint, which exposes no way to read what a key may do, so transfer and redeem stay `unknown` and the connect screen says so. The five keyed venues are unit-tested but not yet run against live accounts.
- **A published install path.** `curl --proto '=https' --tlsv1.2 -LsSf https://usetu.la/install.sh | sh`, plus `brew install hsnice16/tap/tula` and `npm install -g @hsnice16/tula`. The installer checks the download against its published checksum and refuses rather than warns; where the GitHub CLI is present and signed in it also verifies a sigstore-backed attestation proving this repository's workflow built it and refuses on failure, and where it is not it says plainly which of the two was missing and that provenance was not proven; `TULA_REQUIRE_ATTESTATION=1` makes it refuse to install unproven at all. Versions install side by side under `~/.tula/versions` behind a symlink, so going back to one is a link flip rather than a re-download — the direction that matters when a build is showing someone a wrong number. A launcher the user replaced is left alone.
- **Homebrew and npm as second channels.** `brew install hsnice16/tap/tula` on two deliberately-named lines — `tula` lags and is promoted per release, `tula-latest` moves every time — because a bad build here does not fail loudly, it shows someone a wrong liquidation number. Every release also leaves a `tula@<version>` behind it, so a known-good build stays installable after the channels have moved past it; a Homebrew formula holds exactly one version, which made it the only channel with no way back. `npm install -g @hsnice16/tula` resolves one per-platform package and copies the native binary over its launcher, so the installed tula never starts Node; Node is needed to install it, not to run it. All three channels take an exact version: `TULA_VERSION` for the installer, `@<version>` for npm and Homebrew alike — and all three answer to `latest` meaning the newest release that is not a pre-release, which on Homebrew is spelled `tula`. Tapping once with `brew tap hsnice16/tap` makes the bare `brew install tula` work from then on.
- **tula says when a newer release is out, and never installs one unasked.** Once a day the shell resolves GitHub's `/releases/latest` redirect — the lookup `install.sh` already does, and not the JSON API for the reason it avoids it, which rate-limits unauthenticated callers by IP — and prints one line if there is something newer. The request carries nothing about you: no version, no identifier, no query string. `TULA_NO_UPDATE_CHECK=1` stops it. `/update` then prints what it would install and the release page to check it against, because a checksum proves an archive is the one whose hash was published beside it and cannot prove the release is one this project meant to publish; `/update install` is a second word you have to mean to type before anything is downloaded. It runs `install.sh`'s checks in `install.sh`'s order — refusing a checksum mismatch, an archive not listed in `checksums.txt`, and any version not newer than the one running, since `/releases/latest` skips pre-releases and would otherwise offer a pre-release build a silent downgrade. Under Homebrew or npm it declines to move at all and names `brew upgrade tula` instead, so neither is left reporting a version that is not running. Provenance is not checked on this path — that needs the GitHub CLI — and the prompt says so before you answer.
- **Switchable price sources.** CoinGecko still needs no key; CoinMarketCap, CryptoCompare and CoinPaprika can replace it. Exactly one is active, and switching reprices the whole book rather than half of it — a book priced partly by two oracles is the silent inconsistency one-oracle-per-process exists to prevent. Keys are entered in the shell, never on a command line a shell history would keep, and only the active source's key is stored.
- **Sign in with a browser, instead of pasting a key.** `/login` offers `ant auth login` first: it opens a browser and stores an OAuth profile the SDK reads on its own, so tula never sees, handles or stores the token — one fewer secret on disk in a tool whose argument is minimal credential handling. Delegated to the Anthropic CLI rather than reimplemented; a second OAuth client holding a token would be strictly worse than no token.
- **Resizing the window redraws the screen instead of stacking copies of it.** Ink measures a frame by the newlines it wrote, and a terminal that has just narrowed has already rewrapped that frame onto more rows than that — so its next erase ran short and the top of the old frame stayed standing under the new one. One ghost per resize, and a drag is many. Erasing only the rows it missed is not enough on its own: growing the frame mid-reflow scrolls the screen, and rows that go over the top are past recall, so any repair short of a full redraw leaves that many rows blank — under the input line, or as a gap above it. A width change now clears the screen and its scrollback and writes the transcript again at the width it is being read at, which is also what keeps a pane widened after being narrowed from staying wrapped for a width it left. The cost is the scrollback: whatever sat above tula from before it started goes with the redraw. `src/ui/screen.test.ts` drives the real component into a terminal emulator and asserts on the rendered grid, which is the only place any of this was ever visible.
- **ctrl+k searches every command at once.** `/` lists the same surface and filters it by what you have typed, left to right; ctrl+k matches loosely across the whole of it, so `krcon` reaches `/kraken connect` without knowing which venue the verb hangs off. Enter runs what has nothing left to supply and puts anything else on the line with its arguments named. It is ctrl and not cmd because `cmd` never reaches a terminal at all.
- **Nothing moves under the cursor.** The command menu moved below the input line and holds a fixed height, so narrowing it from twenty-one commands to three no longer collapses the block and drags the line you are typing on up the screen. ctrl+k opens as a dialog floating over a dimmed copy of the screen, rather than as a panel that fills it: what you opened the search from is still there behind it, and closing puts the screen back as it was. Leaving a full-screen panel — connecting a venue, or `/login` — puts it back as well: the panel is drawn inside the transcript's own tree rather than in place of it, so returning no longer writes every entry a second time under the copy already on screen.
- **Long output is kept to twelve lines, with ctrl+o for the rest.** A 176-position book was a screenful per answer, and the question that produced it scrolled off before it could be read beside what it returned. What is held back is counted, never dropped; ctrl+o puts it back in place — the transcript grows where it stands, the question stays above its answer, and the terminal's own scrollback is how you read up through it. It is a mode, not a pane: it stays on for output that arrives afterwards, and the footer says so while it is.
- **`/about`** — what tula reads, what it structurally cannot do, where credentials sit, and whether plain English is available. The trust surface on one screen, so nobody reads the README to learn what the binary will not do.
- **[A published site](https://usetu.la/)** — overview, install and the security model. The changelog and the roadmap stay in the repository, where they are edited and read as the same file rather than rendered into a second copy. A separate package with its own lockfile, so its dependency tree never joins the binary's. A link to it unfurls as a card drawn from the same book the front page publishes and the same test recomputes. The frame beside that book works `/`, ctrl+k and ctrl+o on a loop, because the three keys are the whole of the interface a transcript cannot show, and what they open is the command surface this build actually ships rather than a drawing of one. And [`/llms.txt`](https://usetu.la/llms.txt) is the site written once more for the assistants people ask about a tool like this before installing it.
- **The interactive shell**, on Ink. A bordered input with output above it and a live status line beneath — venues, positions, oldest data, whether the model is available. It opens on a banner naming the version, what tula does and which venues the session is reading, beside the mark the site and the favicon carry — the balance the name means, drawn in half-blocks; the banner is written into the transcript rather than pinned above it, so it scrolls away like everything else. `/clear` clears the screen as well as tula's own record of it — each entry is written to the terminal once, so emptying the record alone used to leave every row of it standing and add the command that asked. Line editing, cursor and history are hand-written rather than a dependency, because the front door of a process that reads exchange keys should not be one.
- **`exposure`** — net exposure per asset across every venue, with notional and the venues that contributed. The same ETH held spot, short and pledged is one number. **`breaks`** — everything that can be liquidated, nearest first, with the required move expressed the same way for a perp liquidation price and an Aave health factor. **`shock <ASSET> <PCT>`** — reprice the whole book and report the change, the new health factors, and exactly what liquidates. **`venues`** — per-venue counts, freshness and failures.
- **Plain English over the same vocabulary as the commands.** A line matching a known command runs deterministic code; anything else goes to `claude-opus-5` with adaptive thinking, streamed into the surface. An answer that stops to read a tool goes on saying what it is on and how long it has been — thinking, then the tool by name, then thinking again — for as long as it is working rather than only until the first word arrives, and each turn's prose is its own paragraph instead of running into the last mid-sentence. Its entire tool surface is the risk engine — net exposure, positions, what breaks first, run scenario, venue status — and `scripts/guard.sh` fails the build if `src/agent/**` ever reaches a connector or the secret store.
- **Slash commands with a menu.** `/` opens a filtered list with arguments and summaries; ↑↓ moves, Tab or Enter completes, Esc dismisses. A slash means a command and anything else is a question, with no heuristic to hold in your head. Every venue in the build is a first-class entry carrying its own status inline — position count and freshness, `FAILED`, or `not connected` — and `/<venue>` opens `connect`, `positions`, `breaks`, `status`, `docs`, `disconnect`; once that venue is connected those sit in the top-level list under it, so neither the venue nor what you want from it costs a step of its own. There is no longer a step where you must learn a venue's name to type it into a command.
- **Every venue and price source wears its own mark.** A `●` in that party's colour beside its line in the `/` menu, ctrl+k and the connect screen, so a dozen third-party names are scanned rather than read. Each colour is sampled from that brand's own artwork rather than picked to match tula's, and it is the one thing an unselected row lights up — a mark is identity, not emphasis.
- **Connecting happens in the app**, with the venue's official links on screen at the step that needs them. Connectors declare their own credential fields, which are secret, and their help links, so the flow is generic.
- **Credentials asked for once, and shown on demand.** The sign-in screen appears only when there is nothing to answer a question with, and an `ant auth login` profile counts as a credential — so a browser sign-in is not asked for again on the next start, while the status line beside it reports the model as available. "Continue without one" stays a first-class choice; a pasted key is stored at mode 600 under a reserved key the venue list never returns. `/login` is its own screen rather than the first run again: it names the credential a question would actually go out with — environment variable, stored key, or sign-in profile, in that order of precedence — offers to replace it, and offers to sign out only where there is something tula can genuinely forget. Where it cannot, it says who holds the token instead of showing a button that would not work.
- **CoinGecko price oracle**, batched into one request per refresh, and a session cache — one fetch per shell session, `refresh` to refetch. Cached data is never rendered as live.
- **Canonical position schema** (`src/core/position.ts`) — signed quantities, a stored `delta`, and `asOf` on every position so freshness travels with the number.
- **Secrets store** at `~/.config/tula/credentials.json`, mode 600 enforced on read, with no import path from the agent layer.
- **Kraken connector** — request signing pinned to Kraken's published test vector, balance fetch, and asset normalization for the legacy `X`/`Z` prefixes and `.S`/`.M` yield suffixes.
- **`tula connect <venue>`** — no-echo secret entry, key-scope verification, and refusal of any key that can withdraw. **`tula positions`** — every position across connected venues, with an `as_of` per row and a loud `INCOMPLETE` when a venue fails.
- `TulaError`: user-actionable failures print one line, bugs keep their stack.

### Changed

- **`Net value` is now `Net notional`.** The figure is the sum of each asset's exposure — `delta × price` — so a leveraged perp contributes the whole position rather than the margin behind it. On a book with leverage in it, "value" overstated net worth by exactly that leverage. The number has not changed; the label now says what it has always been, and matches the `NOTIONAL` column above it.

- **Every command on the install page can be copied.** On a phone both the install line and the `gh attestation verify` line scroll sideways inside their frame, which is where selecting one by hand goes wrong. Homebrew and npm had shared one frame holding two alternatives; they are two frames now, because a single copy button over both is a paste that installs tula twice.
- **The site reads on a phone.** Every gap between its sections was a fixed 216px, which on a handset is a quarter of the screen with nothing in it; the spacing and the page's gutter now clamp with the viewport, and a desktop is unchanged. The install page's "what it runs on" table scrolled sideways, leaving the note that answers the question off the screen with nothing to say it was there — its rows stack instead. The header and the footer centre once they wrap, rather than holding the wordmark to one edge and the nav to the other.
- **The security page says which of the two things is measured.** Its egress card ended "Nothing is sent about how you use it" — true of the binary, and read as true of the page by the person reading it, now that the site carries analytics. The binary is unchanged and still reports nothing: no telemetry and no crash reporting, and the once-a-day release check carries nothing about you. The card now names the subject rather than leaving a reader to pick one.
- **The security page says what the code does, and the build now proves it.** Its promises had drifted past their enforcement: it credited `guard.sh` with refusing any order or withdrawal endpoint when the check only ever matched Kraken's, said tula never handles key material while the Coinbase connector loads and signs with a CDP private key, and said the installer refuses what it cannot verify when without the GitHub CLI it installs and warns. Each claim is now either true or gone, and the build fails on an order, withdrawal or transfer endpoint in any connector, on a transaction-signing RPC, and on key handling outside the one connector whose credential is a private key.
- **Nothing says tula cannot place an order full stop.** Trading is coming, and a security promise withdrawn on release day reads as though it was never true. Every surface now carries the front page's own caveat — placing trades will come later — while the promise stated flatly is the one that never moves: funds do not leave a venue. A key that can withdraw is still refused rather than warned about, and always will be.
- **The security page says the credential file is not encrypted.** It is one file, mode 600, plain JSON. A key kept beside the ciphertext would protect nothing and a passphrase would break the commands that run unattended, so the permissions are the whole defence — which is worth saying outright rather than leaving a reader to assume otherwise and put the file in a backup.
- **A wait says what it is waiting on.** The spinner read `working` for the whole of a load and then for whatever came after it, which behind a fetch carrying a 15s deadline per venue is indistinguishable from a hang. It now names each venue as it is read and then the pricing pass, and counts the seconds off beside it — so a slow venue is visibly a slow venue, and the number on screen is how long it has actually taken.
- **Every figure reaches the model already rendered** — `"0.0113679"`, `"$27.75"`, `"-18.4%"`, `"19:24:22 (1s ago)"`, from the same code that draws the tables. It had been answering `0.01136790246459898 ETH, worth $27.753483398047303782` beside a table reading `0.0113679  $27.75`, leaving the reader to decide which was real. Rounding is arithmetic and the model may not do arithmetic; now it has nothing to round.
- **Prices come from CoinGecko's market list** rather than a hand-written 22-asset symbol map. On a live 176-position book that took the unpriced count from 170 to 44. Tickers resolve in market-cap order, with the assets where a wrong price would cost most pinned to explicit ids so they never depend on that ordering.
- **A venue is described in its own terms** — a wallet holds `65 tokens`, an exchange `12 balances`, a lending market `3 positions`, read from the rows rather than the venue because a CEX holds both. "Position" implies a counterparty a token sitting in a wallet does not have.
- **The command menu is grouped and alphabetical** — your book, venues, price source, session, in a fixed order. The previous list had an order only someone who had already learned it could predict.
- **`/exposure` runs when the session opens**, and again after a venue connects, echoed rather than run invisibly so what is on screen is traceable to something the user could have typed.
- Tool activity is named in the user's terms: `reading your positions`, not `get_positions`, collapsing to one line with a count when a tool repeats. The status line ticks, because it claims an age.
- Hyperliquid's thousand-scaled perps (`kPEPE`, `kBONK`) unwind to the underlying, dividing the liquidation price by the same factor the size is multiplied by. Left alone they would neither price nor net.
- The unpriced list is summarised rather than enumerated: a count and the largest few, not 170 symbols across ten lines. A book nothing could be priced from has no total rather than a total of `$0.00` — summing no prices gives zero, and a zero beside a live book reads as an empty account rather than as a price source that did not answer. An account genuinely holding nothing still says `$0.00`.
- **Renamed to tula** — taken from Sanskrit, the balance; the same object Latin calls *Libra*. Binary, config directory, `TULA_*` variables and npm scope all follow. Nothing was published under the old name.
- Every dependency pinned to an exact version, with `bun.lock` committed. A caret range is a standing promise that code nobody has read yet is safe to run in a process holding exchange keys.
- Upgraded to **Ink 7 and React 19**, which requires Node >= 22. All key handling moved into `app.tsx`: the slash menu and the line editor compete for the same arrow keys and Enter, and two input hooks cannot agree on who won.
- The palette moved to a dulled gold (`#c9a227`) — the metal the rest of this is measured against. Saturated yellow was avoided deliberately: in a terminal it reads as a warning, and that meaning is kept in reserve. Red stays semantic.
- `NetExposure.notional` is `Decimal | null`. Zero would read as no exposure.
- The credential store resolves its path per call, so `TULA_CONFIG_DIR` works in tests rather than being frozen at import.
- `connect` in a non-TTY with no piped input says it needs an interactive terminal instead of reporting the values as invalid.

### Security

- **A venue's key can no longer be carried off by a redirect.** `fetch` strips `Authorization` when a redirect crosses to another host and strips nothing else, so Binance's `X-MBX-APIKEY`, Kraken's `API-Key` and CoinMarketCap's `X-CMC_PRO_API_KEY` would all have been re-sent to whatever the `Location` named. Anything able to shape a venue's response — an intercepting proxy, a rogue CA, an open redirect at the venue's edge — could have collected the key by answering `302`. Redirects are now refused outright; the two requests that legitimately follow one, both in `/update` and neither carrying a credential, opt back in and `guard.sh` fails the build on a third.
- **The model endpoint is pinned.** The Anthropic SDK reads `ANTHROPIC_BASE_URL` from the environment, so one line in a shell profile — from a dotfiles repo, a devcontainer, a package's install script — would have sent every question, the whole computed book with it, and the API key to a fourth party, while the screen still said Anthropic. tula now states the host.
- **A venue's error text can no longer repaint the screen that refuses its key.** Error strings from a venue were capped and flattened everywhere except the connect path, which rendered them raw — and Ink draws text verbatim. An escape sequence in a JSON-RPC error from a hostile `TULA_ETH_RPC` could rewrite the line above it, which at that moment is the scope refusal. Both connect paths now go through the same cap as the rest.
- **A published checksum is checked for being a checksum before it is printed.** It is bytes from a downloaded file, splitting on whitespace does not split on ESC, and the message carrying it is drawn in the one case the checksum exists for — so a failing archive could have repainted the line reporting the failure.
- **An address is checked against its own checksum.** A single mistyped character used to be accepted and read somebody else's book under it, silently and with every number beside it correct. EIP-55 is verified where a mixed-case address carries one; an address typed in one case has no checksum to check and is still accepted, since refusing those only teaches people to lower-case until it is taken.
- **An attestation now has to come from the release workflow, not merely from this repository.** Any workflow holding `attestations: write` could mint one the installer accepted, so a proposed change to CI was enough to sign an arbitrary archive. `install.sh` pins the signing workflow.

- **A venue's endpoint URL no longer travels with its error.** `TULA_ETH_RPC` is offered as the way to point tula at your own Ethereum node, and the two providers people actually point it at — Alchemy and Infura — carry the API key in the URL path. A non-200 from that node was reported as `RPC <the whole URL> returned HTTP 429`, which is printed on screen and handed to the model as a failed-venue string. Every such message now names the host and nothing else, which is what `core/http.ts` already did for a timeout. The token list is the same fix.
- **A credential is no longer written into a directory anyone can replace it in.** The store refuses to *read* out of a world-writable config directory, but the check sat after the branch that returns early when there is no file yet — so the very first `connect` on a machine where `~/.config/tula` already existed loose wrote the key into it and reported success, and the refusal arrived on the next read, with the secret already on disk. It refuses before the first write now.
- **An attestation now only ever exists for a published release, so one that verifies is one that shipped.** A rehearsal run of the release workflow used to mint one too, and `install.sh` accepts any archive carrying an attestation for this repository — so a build made from an arbitrary branch, and never released, would have verified as genuine.
- **`TULA_VERSION` cannot redirect the download.** curl resolves dot-segments in a path, so a version containing `../` walked the download base out of this repository and onto another one — `checksums.txt` included, which made the check agree with whatever it had just fetched. The origin being hardcoded is the argument the installer rests on; the version is now checked before it reaches a URL, as `/update` already checks the tag it reads.

### Fixed

- **tula hands the terminal back, however it ends.** Pointing at a list turns on mouse reporting, and the undo was a React cleanup — which covers unmounting and nothing else. Closing the window (SIGHUP), a `kill` (SIGTERM) or a crash left the mode on afterwards, so moving the pointer wrote escape codes at the user's own shell prompt and selecting text stopped working, with no way to know that `printf '\e[?1006l\e[?1003l'` was the cure. The undo is now registered with the process as well, and re-raises so the exit code is still the one the signal meant. Bun does not reach `exit` from an uncaught throw the way Node does, so crashes are covered separately.
- **A swept mouse no longer types into the command line.** Reports were matched one per chunk, but mode 1003 reports every movement and a hand crossing the screen sends them faster than stdin is drained — so a run of them failed to parse and went in as the punctuation it looks like, `[<35;10;5M[<35;11;5M…`. They are read as a stream now, and a report split across two chunks is held rather than typed.
- **Every failed venue keeps its own way out.** The suggestion to run `/<venue> status` was suppressed when *any* failure already named a remedy, and a venue quoting a URL counts as one — so a single failure mentioning a link took the way out away from every other venue that had failed beside it.
- **A venue that failed is no longer described as an empty account.** It was counted among the ones that "returned nothing", so a book nobody could open was reported as "connected and returned nothing — either the account is empty, or it is not the one you trade with", two lines above an `INCOMPLETE` block saying it had never been reached.
- **A bug in tula says it is one.** An unexpected error reached the screen as a bare line — `TypeError: x is not a function` — with nothing to do about it and nowhere to send it. It now says it is a bug and names the issue tracker.
- **Every error names a way out.** A dead Ethereum node, a Hyperliquid 5xx, a reserve list that came back empty and an incomplete stored credential all stated a problem and stopped. Coinbase's two signature-format checks went the other way: they are tula disagreeing with itself, nothing a user can act on, so they keep their stack trace instead of posing as advice.
- **Hyperliquid's clock cannot make a stale snapshot read as fresh.** Its rows are stamped with the venue's own time, and a venue running ahead of the machine pinned every one at "0s ago" while the data behind it aged.

- **`/` and ctrl+k now list the same commands.** They were built from two functions and disagreed about which commands existed: after connecting a venue, ctrl+k offered `/hyperliquid connect` — the row that replaces a stored address — while typing `/h` offered `/hyperliquid` and stopped. The subcommands were reachable, behind a space nothing on screen mentioned. Both lists are now the one surface; only the matching differs, prefix under the input line and fuzzy in the dialog.
- **Connecting says what it is doing.** Storing the credential is instant; reading the venue is not, and that read ran with the spinner off — so the screen sat on "Connected Hyperliquid." with an idle prompt for as long as the venue took, then printed a book. The wait is now covered end to end and names the venue being read.

- **A position already being liquidated no longer reads as the safest row on screen.** Below a health factor of 1 the move to liquidation is zero, and an unsigned zero renders `+0.0%` — in a column where a plus means the price must *rise* to reach the trigger. An Aave account at 0.50, underwater and being liquidated, was drawn beside positions with room to spare and handed to the model as a 0% rise. Such a row now says `liquidatable now`, in the tables and in the tool result both.
- **A zero or unparseable price is no longer a price.** `new Decimal(0)` is an object and therefore truthy, so a zero passed every downstream guard and rendered a real holding as `$0.00` with no unpriced note — the defect this project names first. `NaN` and `Infinity` do not throw either, and one of them turned every total in the book into `$NaN`. All four price sources now go through one gate, which also fixes a `null` quote from CryptoCompare throwing a raw `DecimalError` that cost every other price in the batch.
- **`/refresh` says when it did not refresh everything.** It reported a count and exited 0 while venues were failing — the one command somebody runs *to recover from* a failure was the one hiding it. It now carries the same `INCOMPLETE` block every other command does. Its venue count was wrong in both directions as well, counting sub-account labels twice and connected-but-empty venues not at all.
- **The model is told when the book it is quoting is incomplete.** Every command has carried `INCOMPLETE` since the first release; the agent's numeric tools carried nothing, so a book missing a venue was narrated as a total with a system-prompt rule as the only thing standing against it. All four now return what failed alongside the figures.
- **An Aave reserve that failed to load is no longer read as a zero balance.** A failed `eth_call` inside a batch returns null, and null defaulted to a zero quantity, eighteen decimals and the symbol `UNKNOWN` — so a dropped *debt* leg made the book look richer and safer while the health factor beside it still rendered, two `UNKNOWN` reserves netted together as one asset, and a six-decimal balance scaled by ten-to-the-eighteen read as nothing. The venue is now reported failed instead.
- **A Coinbase account holding more than 250 currencies is read to the end.** The first page was taken as the whole account, so the tail vanished into a net exposure that reported itself complete.
- **USDD is priced rather than assumed.** It sat beside USD in the set of tickers worth one dollar by definition, under a comment that justifies USD alone. It is a priced, de-peggable asset, and pinning it valued it at par through exactly the event its holder needs the real number for.
- **The site stopped offering an address-only venue a key, again.** The fix shipped in the binary and the homepage kept the old wording, because the fixture behind the test that pins that page built its venue rows without the flag that separates an address from a key — so the test compared the page against a drawing of the wrong build. `/<venue> status` also went on claiming a key had been "checked as read-only" for Kraken, Stripe and Circle, which expose no way to check exactly that, contradicting what the connect screen had already said honestly.

- **A slow `/update install` no longer ends in a stack trace.** The deadline `request()` carries is a venue-poll number, and the abort signal it attaches stays on the response body — so any connection that could not pull tens of megabytes inside 15 seconds threw a raw `TimeoutError` past every handler that knows what a tula failure looks like. Downloads now carry a deadline of their own, and a download that stops part-way says so and installs nothing. An unpack that fails says the same rather than printing a stack trace.
- **A Binance call that fails is no longer read as an empty result.** The account loads from two calls, and the second was wrapped in a catch meant for a key without futures permission — which also swallowed a timeout, a 5xx and a gateway error page, loading the account with no `INCOMPLETE` and exit 0. Only Binance's own permission codes are treated that way now. (Binance's futures permission grants futures *trading*, so a key that could read those positions is refused at connect; the path is kept correct against the day that changes.)
- **A Homebrew formula is never rendered with an empty checksum.** `set -e` does not fire for a command substitution inside a heredoc, so a `checksums.txt` missing a platform produced a valid-looking formula carrying `sha256 ""` and exited 0 — which the release job commits and pushes, and every `brew install` on that platform then fails as a checksum mismatch, after the release is already public.
- **A venue holding nothing no longer reports an age for data it does not have.** `/` and ctrl+k drew `0 balances · 0s ago`, because reducing over no rows answers with the current time.
- **`breaks` and `shock` no longer answer for a book they never read.** With nothing connected, `breaks` said "Nothing here can be liquidated" and `shock` priced a $0.00 portfolio and reported that nothing liquidated at that level — three true figures adding up to reassurance about a portfolio that was never fetched. Both now say what `positions` and `exposure` already said, and name the way out.
- **A venue that failed is no longer reported as safe.** `/<venue> breaks` and `/<venue> positions` left out the `INCOMPLETE` block every other command carries and exited 0, so a lending venue nobody could reach answered "Nothing at aave can be liquidated" — which to a script is the definition of fine.
- **Address-only venues are no longer offered a key.** Wallet, Hyperliquid and Aave are read from a public address and hold no credential, but the menu and ctrl+k described connecting them as "add or replace this venue's read-only key", and `/<venue> status` claimed a key scope had been verified. A tool that asks a wallet for a key is the shape of a phishing page. `status` also reported "oldest, 0s ago" for a venue holding nothing, because the age of no rows was read as the current time.
- **`/forget <venue>` takes effect in the shell it was typed in.** Only `/<venue> disconnect` refreshed what the session believed was connected, so after `/forget` the menu went on listing the venue as live and `status` went on answering from the connected branch.
- **Installing twice leaves one line in your shell profile.** The check for a line already added looked for the default spelling of the path rather than the one it had written, so an install under `TULA_INSTALL_DIR` appended another block every run.
- **The installer names every tool it needs.** A missing `grep` surfaced as the checksum lookup coming back empty, which the script reports as an archive missing from `checksums.txt` — a missing tool read to the user as a supply-chain attack.
- **One wording for the trading promise, and it is the one that can be extended.** `install.sh` closed with "it cannot place an order or move funds" — the flat form every other surface avoids, because it becomes a withdrawn security promise the day trading ships — and nothing was checking that file. `/about` had drifted to a fourth phrasing of its own. Every surface now carries "placing trades will come later", and the test that holds them together accepts only that.
- **npm is described as the channel it is.** The install page said npm proved nothing about who built the binary and sent the reader to another channel for that, while the release publishes it with `npm publish --provenance` — sigstore provenance the reader could have checked. What is true is narrower: the GitHub attestation covers the release archive, and npm repacks it into something that attestation cannot describe.
- **The verify command carries the flags the page argues for.** The install page spends a legend on `--proto '=https'` and `--tlsv1.2`, then handed the reader a bare `curl -fLO` for the one download they make by hand — the download whose whole purpose is checking who built the binary. `install.sh` printed the same bare command in its unverified fallback.
- **The README's security claims match the code again.** Its egress list was exhaustive and named neither the Ethereum node, the token list nor the daily release check; its attestation promise said the installer "refuses rather than warns", which is what the security page had already been corrected for and what happens only where the GitHub CLI is present and signed in.
- **Every asset symbol is bounded.** Binance and Hyperliquid passed the venue's raw string straight into a position, and a symbol is printed in every table and sent to the model with every position. Every connector now arrives at one place that caps it at 32 characters and strips control characters, rather than one chance per connector to forget.
- **A failed venue's own error text is bounded too.** It is drawn on screen and returned to the model by `get_venue_status`, and its content is whatever the venue put in an error body — Binance's `msg`, 120 characters of a Coinbase response, Kraken's error array. Now capped at 200 characters and flattened to a single line in `src/cli/session.ts`, so a venue cannot answer with something that reads as a second message. It also fixes the rendering: `/status` prints one indented line per failure, and a multi-line message used to break out of that list.
- **A token symbol read from a contract is bounded before anything renders or reads it.** `decodeString` took the length prefix from the response and returned whatever came back, and an Aave reserve's symbol becomes a position's asset name — rendered in the tables and handed to the model as a tool result. Whoever answers as the Ethereum RPC chose both the prefix and the bytes. It is now capped at 32 bytes with control characters and line breaks stripped, so a symbol cannot arrive carrying its own line. The security page had claimed memos, NFT metadata and protocol descriptions were the hostile surface; tula reads none of those, and did not mention the one string it does read. Both say the same true thing now.
- **`SECURITY.md` no longer promises a 72-hour acknowledgement.** One person maintains this; a policy that misses its own stated clock is worse than one that never set it. It now says what it can keep — a reply usually within a week, and what to do if a week passes — and names the third injection surface it had left out.
- **`SECURITY.md` names every host tula contacts.** It said two destinations, both of which you choose, and that nothing else was contacted to build the view — omitting the public Ethereum RPC and the token list, which are defaults rather than choices and each see the address being read. `guard.sh` also now fails when the `gh attestation verify` example in `SECURITY.md`, `README.md` or the install page names a release other than this one: a reader copies that line verbatim, and a stale filename reports as a failed verification.
- **The `gh attestation verify` command the installer prints now names something that is actually attested.** The attestation's subject is the release archive; the installer pointed the command at the extracted binary, so anyone following it to check provenance for themselves got a rejection and had no way to tell that from a real one. It now prints the download and the archive. The security page said every channel could be checked that way, which is not true of npm — that repackages the binary into its own tarball, which carries no attestation; the page and `SECURITY.md` say so and point at the install script or Homebrew where provenance has to be proven.
- **The credential store no longer follows a link, or trusts a directory anyone can write to.** `stat` reports a symlink's *target*, so a link planted at `credentials.json` passed the 600-mode check and then took the next write wherever it pointed — demonstrated writing a real key and secret into an attacker-chosen file, silently. It now `lstat`s and refuses anything but a regular file, refuses a config directory that is group- or world-writable, checks both before reading rather than after, and writes through a temporary file and a rename so an interrupted write cannot truncate the store.
- **An unreachable venue hung the whole tool.** No outbound call had a deadline, so a venue that accepted the connection and went quiet — a rate-limited exchange, a saturated public RPC, a half-open NAT connection — blocked the refresh for as long as the OS was willing to wait. Measured at 76s for one unreachable RPC, with the shell spinning and no way out but Ctrl-C. Every call now goes through one `request()` with a 15s deadline, and `guard.sh` fails the build on a bare `fetch`. The deadline is a raced timer rather than `AbortSignal` alone, because the signal bounds the wait for a response and not for a connection: against a black-holed address a 3s signal took 75s to fire. A one-shot command now also exits once its output is written, instead of waiting on the socket of a venue that already failed.
- **An Anthropic outage printed its raw JSON envelope.** `Error: {"type":"error","error":{"type":"overloaded_error",...}}` tells someone with money at risk nothing they can act on. Failures are now translated — which side failed, whether waiting helps, and that commands answer without the model — and a transient overload is retried five times before anyone sees it. A failed request no longer leaves the abandoned question in history, where the next one would be answered in its place.
- **Plain English could answer "nothing is connected" about a connected venue**, because nothing forced a first load before a question. Relatedly, `/exposure` reported an empty book straight after a venue connected: storing credentials re-armed the open-with-state effect, which ran against the pre-connect cache and printed "nothing to measure" over a wallet that had just returned four positions.
- **An empty book told you to connect a venue you had already connected.** The message now depends on the credential store: no venue is a connect prompt; a connected venue holding nothing names the venue, its status command and `/refresh`.
- **A connected venue holding nothing vanished from `/venues`.** Rows were built from positions, so a venue that succeeded and returned zero was indistinguishable from one never connected — the silent gap this tool exists to close.
- **Every command from the menu took two Enters.** With the `/` menu open, Enter completed the highlighted command the way tab does — the menu closed, the line filled in, and nothing ran until it was pressed again, which reads as the first press having been missed. Enter now runs what is highlighted and tab is what completes it, the split ctrl+k already used. A command with arguments left to supply is still only completed: they cannot be guessed.
- **ctrl+k answers the mouse.** It was keyboard-only: nothing asked the terminal for mouse reports, so a scroll went to the terminal's own scrollback — which the dialog is covering — and the list sat still. The pointer now reaches it the way it reaches any other dialog. The row under it lights up, a click runs that row, a click on the screen outside closes it, and the wheel scrolls one row a notch against a scrollbar that says how far down the list this is. Tracking is on while the palette is open and only then: it takes drag-to-select and scrollback away from the terminal for as long as it is on, and the transcript is the part people copy numbers out of. A report arriving with the palette closed is swallowed rather than typed onto the line.
- **So does the `/` menu.** It sits in the frame rather than floating over it, so where it lands depends on where the transcript left the cursor — at the bottom of the screen once the session has filled it, part-way down before that, and a click that guessed would run a different command than the one under the pointer. The terminal is asked where its cursor is, which is the one fixed point tying the pointer's absolute rows to a block drawn wherever the frame ended up. A terminal that does not answer leaves the menu on the keyboard and the wheel, which need no such anchor.
- **The wheel moves the list, not the cursor.** The window used to be derived from the selection, so the first notches walked the cursor down rows already on screen and nothing moved — a list that ignores the wheel until it abruptly does not. Scrolling moves the window itself and carries the selection only as far as keeping it on screen requires: enter still runs something you can see. The arrow keys get the other half of that fix — the cursor moves inside the window and takes it along at the edges, rather than the list sliding on every press.
- **ctrl+k listed two "price source" sections, and offered CoinGecko a key it has none of.** The palette put every subcommand in a run after every top-level command, so the sections it draws headings for were reached twice — once for the sources, again for everything under them. Each source now carries its own subcommands, and a keyless source is no longer offered `connect` or `disconnect`: there is nothing to paste and nothing to forget, and `/coingecko disconnect` had read "fall back to CoinGecko". The "N more below" count also read off the whole list rather than the visible window, so it never moved as you arrowed down and still promised more at the last row — which reads as a list that does not scroll.
- **A typed space was deleted before it reached the input line.** The paste handler normalised newlines then trimmed, so a lone `" "` became `""`, making `/shock ETH -20` and every venue subcommand impossible to type.
- **An `ant auth login` profile is now recognised as a credential.** The SDK reads it on its own, so a signed-in user was told they had none and asked for an API key.
- Venue subcommands did not work one-shot: `tula wallet status` printed the usage banner, and once the parser knew the venues, every one still reported "not connected" because the dispatcher was never handed the stored ones.
- A misused command exits non-zero — `shock ETH banana` reported success, so a typo in a script looked like it worked.

### Removed

- **The demo venue and every piece of fake data.** Any public address exercises the full cross-domain path against real data, so a fixture sitting beside real venues was a liability rather than a convenience. `TULA_DEMO` is gone; the cross-domain scenario survives as a connector defined inside the test file that asserts on it.

### Notes

- `WETH` normalizes to `ETH` — redeemable one-for-one and trustlessly, so it is the same exposure. `wstETH` and `weETH` are not, and are left alone; `WBTC` carries custodian risk and is priced separately.
- Stripe quotes in each currency's minor unit and not all have two, so dividing everything by 100 would report a JPY balance as a hundredth of itself.
- bun's `node:crypto` rejects `dsaEncoding: 'ieee-p1363'`, so Coinbase's ECDSA signatures are converted from DER to JOSE by hand; without it every request would present as a rejected key.
- Address-only venues report `canTrade: false` and `canWithdraw: false` as proven facts — there is no credential to over-scope. That is a real contrast with Kraken, and the connect screen says which kind you are looking at.
- Without an Anthropic key the product is unchanged except that plain English is unavailable. Every view has a command behind it.
- The agent surface was planned for the execution milestone and pulled forward to the shell. The hard boundary did not move with it.
- The compiled binary carries `react-devtools-core` (+2.3 MB): Ink imports it statically from a module it only loads when `DEV=true`, and marking it external breaks the binary at startup.
- The risk-engine work landed alongside breadth rather than after it. Getting the maths right against a fixture was cheaper than discovering it wrong against a live perp position.
- `KeyScope` is tri-state. Kraken exposes no endpoint reporting a key's permissions, and every endpoint gated on trade permission mutates an order, so `canTrade` is `unknown` rather than guessed at. Withdraw scope is provable, and is proven.
- Kraken margin and open orders are not read yet, so on a margin account this is not a complete Kraken picture.
